# ADR-001 — PostgreSQL и EF Core

- Статус: принято для учебного прототипа
- Контекст: требуется реляционное хранение пациентов и визитов; данные должны иметь предсказуемые ключи и отношения.
- Решение: PostgreSQL 16 и Entity Framework Core 8 (Npgsql). Точки интеграции реализуются HTTP API.
- Плюсы: FK, транзакции, типизированная модель C#, независимые тесты.
- Минусы: развёртывание PostgreSQL, управление миграциями, требования к аудиту и защите PII.
- Альтернативы: SQLite (удобен локально, но не выбран как основная БД); MongoDB (не нужен гибкий документный формат).
- Следствия: релизные миграции должны ревьюиться; в репозитории запрещены реальные выгрузки пациентов и пароли; резервное копирование и восстановление должны тестироваться отдельно.

В реализации для Development используется `EnsureCreated`; в Production следует использовать проверенные миграции `dotnet ef migrations`. Этот документ не подтверждает промышленную готовность системы.
